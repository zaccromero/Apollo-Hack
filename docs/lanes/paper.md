## Integration contract

```python
from backend.paper import PaperService, PaperAPI
paper = PaperService('/dedicated/persistent/path/apollo-paper.sqlite3')
api = PaperAPI(paper)
status, payload = api.handle(method, path, json_body)
```

Stdlib only; the parent directory must exist. One local portfolio per database. Integrator owns server binding, account/auth isolation, JSON transport, credentials and error logging. This adapter is for a local single-user demo, not an unauthenticated public financial service. Do not pass research/source databases. Do not reset on startup. Decimal values are JSON **strings**; never parse/round them with binary floating-point for order math.

Default virtual cash is `10000.00` USD. `seed_demo=True` seeds nine illustrative instruments plus one fictional copy strategy only when absent. **Every seeded price is DEMO**, even if a research card has cached factual data. Linked pages identify the security/exposure, not the illustrative price. Paper preview and confirmation must display the paper quote's own provenance. Research can replace prices using the trusted `register_catalog` seam; this is never exposed to clients. The optional `sync_research_catalog(paper, research.catalog())` bridge checks identities/terms/allocations; it **never reads research.quote** or promotes historical cache values into executions. Execution prices remain stable paper DEMO fixtures. Only an explicit record.paper_quote `{price,status:"demo_fixture",is_demo:true,as_of:<timezone ISO string>,source_url?:...}` can update a future paper preview; existing previews remain immutable. The integrator need not call this bridge. Research cards should expose a separate paper_quote matching the engine, while retaining historical quotes as nonexecutable research data.

Stable identities shared with research: `AAPL`, `WINA`, `SPY`, `GLD`, `BTC-USD`, `VNQ`, `AAPL_20261120_C350_DEMO`, `USDC-USD_DEMO`, `DEMO_USD_BOND_20281115`, `DEMO_PATIENT_BUILDER`. Paper kinds use explicit `commodity_exposure` and `real_estate_exposure` for research `commodity` and `real_estate`; GLD/VNQ use fund/trust share math, not direct property or physical commodity ownership. A person/strategy is never an Instrument. Options have integer contracts, premium × multiplier (100) × contracts, exact underlying/strike/right/expiry identity, no exercise/settlement/shorting. Expired positions retain a conspicuous **unsettled snapshot** label, not an invented settlement or live valuation.

`thesis` is `{reason,risk,invalidation}`, optional text strings. A legacy thesis string fills reason only; risk/invalidation remain visibly missing. Decision actions: `pass`, `watchlist`, `interest`, `remove_watchlist`, `save_thesis`. An interest action never buys. UI needs a distinct confirmation sheet/button showing asset identity, units/contracts, quantity, multiplier, snapshot price/provenance, cash impact and paper label. Order preview lasts five minutes and does not reserve cash. Confirmation atomically checks actual available cash/holdings again. A repeated confirmation returns the same receipt, including across service restart and concurrent clients. Stable `client_request_id` retries return the original preview; different requests sharing a key fail with `idempotency_conflict`.

Copy preview creates one atomic basket from sourced/labeled allocations. It rounds allocations down, respects quantity steps and contract units, leaves uninvested rounding cash in the account, and confirms through the same order route. Preview contains the strategy's attribution/provenance and all constituent quote snapshots. UI must not call this buying a person.

Reset requires a fresh preview token and exact confirmation phrase, invalidates pending previews and clears current positions/watchlist. Historical transactions and decisions are retained under prior account epochs, not destroyed. Existing confirmed-order retry receipts remain idempotent after reset and **do not** repeat the trade.

Errors: `(400|404|409, {error:{code,message},mode:"paper"})`; no mutations on errors. Examples include `confirmation_required`, `insufficient_funds`, `invalid_quantity`, `unknown_asset`, `expired_option`, `expired_preview`, `asset_identity_conflict`. Import errors or SQLite operational failures are for the host to log/report, not silently relabel as successful game state.
